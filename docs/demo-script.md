# 展示腳本(8 分鐘)

前置:中央服務已啟動,兩台以上機台已完成 `prepare` 與 `pair`,大螢幕開在 `/display/`,
準備兩個帳號(同時執行上限預設 2,兩個帳號才會同時點亮三台設備)。

| 時間 | 畫面 | 操作與重點 |
|---|---|---|
| 0:00–0:45 | 工作台 | 說明情境:課堂作業要轉逐字稿,自己的筆電跑不動;校內的 GPU 課餘時間閒置 |
| 0:45–1:30 | 我的設備 | 機主取得配對碼、機台 `enable`、網站開啟分享。強調設備由機主自己控制 |
| 1:30–3:00 | 工作台 | 上傳 `demo-assets/introduction.wav` 與數張圖片,說明每個檔案是一件獨立工作 |
| 3:00–4:30 | 大螢幕 | 工作分別派到不同設備,顯示 GPU 使用率與佇列;兩個帳號輪流取得設備 |
| 4:30–5:30 | 我的設備 | **關閉其中一台的分享**,大螢幕顯示該工作回到排隊,並由另一台接手完成 |
| 5:30–6:30 | 工作台 | 下載逐字稿、字幕與放大後的圖片;說明成果只有本人看得到 |
| 6:30–7:30 | 驗收表 | 說明哪些已實測、哪些待辦(`docs/acceptance.csv`),以及安全範圍(`docs/architecture.md`) |
| 7:30–8:00 | 收尾 | 節省的不是雲端費用,而是讓既有設備在課餘時間被用到 |

注意事項:

- 示範前先以受測帳號實際跑過一次完整流程,確認設備狀態與網路。
- 「機主收回設備」是本專案最關鍵的一段,務必留足時間。
- 素材為離線合成語音與團隊產生的校準圖片,說明時要明講,不宣稱是真人受訪或品質評估。
- 若現場網路不穩,`prepare` 後的工作容器不需連外,但中央服務與機台之間的區網必須可通。
